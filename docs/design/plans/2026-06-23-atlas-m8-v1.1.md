# Atlas M8 — v1.1 Backlog Implementation Plan

**Goal:** Clear the documented v1.1 backlog on top of the shipped v1.0.0 platform, ending with the full gate green: (1) a **global user-management** surface — admin-only endpoints + an Angular admin panel to list / create / promote-demote / reset-password / delete users; (2) an **audit log of write operations** — a catalog-backed append store, an admin-only listing endpoint, and an Angular viewer; (3) an **editable database-settings** form in the Explorer wired to the already-shipped `PATCH /api/db/:name`; (4) **inline AQL error squiggles** — a CodeMirror 6 decoration over the offending range in the console, complementing the existing caret banner.

**Architecture:** No new packages. Layered so the work parallelizes without file conflicts:

- **Foundation (server + protocol + client + web SDK seam)** — `@atlas/protocol` gains request/response zod schemas + types; `@atlas/core` is **unchanged** (audit is stored as catalog nodes, dogfooding the engine, exactly like users/tokens/sessions); `@atlas/server` gains `CatalogService` user-admin + audit methods, a `requireAdmin` preHandler, two new route modules (`routes/users.ts`, `routes/audit.ts`) registered in `app.ts`, and audit-recording calls threaded into the existing write paths; `@atlas/client` gains pass-through SDK methods; `apps/web/src/app/core/atlas-api.ts` gains the matching pass-throughs **so web feature work only consumes `api.*` and never re-touches the SDK seam**.
- **Web admin** (`apps/web/src/app/admin/*` only) — two new stores + panels + two new tabs in `admin.ts`/`admin.html`. Touches nothing outside `admin/`.
- **Web workspace** (`apps/web/src/app/workspace/*` only) — db-settings form wired into the workspace topbar; squiggle decoration in `aql-editor.ts` driven by the existing `ConsoleError` signal. Touches nothing outside `workspace/`.

The two web slices touch **disjoint** directories, so they can be built independently after Foundation lands the SDK methods they call.

**Tech Stack:** Existing only — Node ≥22, pnpm 9.15.4, TypeScript 6, Vitest 4, ESLint 10, Prettier 3 (`singleQuote`, `printWidth:100`), Fastify 5 (`@fastify/cookie`/`cors`/`websocket`/`static`), `@node-rs/argon2`, zod 3; Angular 20.3 (standalone, signals, zoneless) with `@angular/build:unit-test` (jsdom, `providersFile: src/test-setup.ts`) and Playwright e2e. **No new runtime dependencies.** Library code uses ESM `.js` import extensions; Angular code uses bare specifiers. Library tests: `pnpm vitest run <path>`. App tests: `pnpm -F web exec ng test --watch=false`. e2e: `pnpm -F web e2e`. CodeMirror 6 (`@codemirror/view`, `@codemirror/state`) is already a dependency of the web app.

**Spec:** `docs/design/specs/2026-06-10-atlas-graph-platform-design.md` — §6.2 (permission matrix; server-admin vs per-db roles), §6.5 (**the audit-log of write ops was acknowledged and explicitly deferred to v1.1 — this milestone delivers it**), §9 (one `AtlasError` hierarchy → problem-details → SDK → UI). Backlog source: `~/.claude/.../memory/m7-hardening-followups.md` items 5–9 and `atlas-v1-shipped.md` deferrals.

**Existing code anchors (verified against source on 2026-06-23):**

- **Catalog** (`packages/server/src/catalog.ts`): dogfoods an Atlas db. Has `createUser(username, hash, isAdmin)`, `findUser → {username,passwordHash,isAdmin}|null`, `anyUserExists()`, `deleteSessionsForUser(username)`, plus database/role/token/session CRUD. **Missing:** `listUsers`, `deleteUser`, `setUserAdmin`, `resetPassword`. User nodes carry `{username, passwordHash, isAdmin, createdAt}`; unique index on `(User, username)` (lines 33–37). Constant `nowIso()` (line 305) returns a **fixed** ISO string — do **not** reuse it for audit ordering. Private lookups use the fluent API (`this.db.graph().nodes('User').where(...).first()`).
- **Auth** (`packages/server/src/auth.ts`): `requireAuth(catalog)` preHandler sets `req.principal = {username, isAdmin}`. `requireCapability(catalog, principal, dbName, cap)` is the per-db matrix. **No `requireAdmin` exists.** `HttpError(status, code, message)` from `errors.ts`.
- **Route module pattern** (`packages/server/src/routes/tokens.ts`, `databases.ts`): export `async function register<X>Routes(app, ctx)`, `const auth = { preHandler: requireAuth(ctx.catalog) }`, parse body with a `@atlas/protocol` zod schema, `void reply.status(201|204)`. Registered in `packages/server/src/app.ts:54–61`. `PATCH /api/db/:name` already exists (`databases.ts:35–41`, requires `admin-db`, calls `catalog.patchDatabase(name, description)`).
- **Write paths to audit** (record AFTER the mutation succeeds, never on the read path): `routes/data.ts` node/edge create/patch/delete; `routes/io.ts` import + seed; `routes/databases.ts` create/delete/patch + role grant/revoke; the new `routes/users.ts`. Write **queries** (`routes/query.ts`) — record a single `query:write` entry when `capabilityFor(statement)==='write'`.
- **Protocol** (`packages/protocol/src/wire.ts` + `index.ts`): zod schemas re-exported as both value and inferred type (e.g. `CreateTokenReq`, `PatchDbReq`, `dbNameSchema`, `DbInfo`, `UserInfo`, `RoleName`). Follow that exact dual-export style.
- **Client SDK** (`packages/client/src/index.ts`): single-file isomorphic client; methods like `listTokens()`, `revokeToken(id)`, `getDatabase(name)`, `grantRole(...)` wrap `fetch`. Add the new methods + re-export new types.
- **Web SDK seam** (`apps/web/src/app/core/atlas-api.ts`): thin `@Injectable({providedIn:'root'})` pass-through to `@atlas/client`. Add one method per new endpoint.
- **Web admin** (`apps/web/src/app/admin/`): `admin.ts` holds `signal<AdminTab>` (`'tokens'|'roles'`) + `admin.html` `@switch`; panels are standalone + `FormsModule`; stores are `@Injectable({providedIn:'root'})` with `signal()`/`asReadonly()` + injected `AtlasApi`, exposing `load()`/`error()`. Mirror `tokens.store.ts`/`tokens-panel.ts` + their `.spec.ts`.
- **Web workspace** (`apps/web/src/app/workspace/`): `aql-editor.ts` builds a CodeMirror `EditorView` (`this.view`) with `lineNumbers/history/aql()/autocompletion/keymap`; the editor is a `viewChild` of the console parent. `console.store.ts` exposes `error()` as `ConsoleError {code,message,line?,column?,snippet?}` (1-based line/column). `workspace.ts` topbar (`workspace.html`) shows the db title; `getDatabase(name)→DbInfo` and the new `patchDatabase(name,{description})` are the data hooks. Picker (`picker/picker.html`) shows `db.description`.
- **Test bootstrap (server)**: `packages/server/test/*.test.ts` — `buildServer(loadConfig({ATLAS_DATA_DIR: tmp, ATLAS_SECRET: 's'.repeat(32)}))`, drive via `app.inject({method,url,payload,headers})`, session cookie `atlas_session`. For admin tests, the bootstrapped admin user requires `config.admin` — set `ATLAS_ADMIN_USER`/`ATLAS_ADMIN_PASSWORD` in `loadConfig` (verify the exact env keys in `config.ts`) or create+promote via catalog.
- **Test bootstrap (web)**: `TestBed` + mock `AtlasApi` via `{provide: AtlasApi, useValue: {…vi.fn()}}`; `src/test-setup.ts` provides `provideZonelessChangeDetection()`.

## Task 1 — Foundation: server, protocol, client, web SDK seam

Owner: one implementer (sequential). Verify with `pnpm build` + `pnpm vitest run packages/server packages/protocol packages/client`.

- [x] **Protocol** — in `wire.ts` add zod schemas + dual exports: `CreateUserReq {username: string(min1,max64), password: string(min8), isAdmin?: boolean}`, `UpdateUserReq {isAdmin: boolean}`, `ResetPasswordReq {password: string(min8)}`, `UserSummary {username, isAdmin, createdAt}`, `AuditEntry {seq: number, at: string, username: string, action: string, target: string, detail?: string}`, `ListAuditQuery {limit?: number(int,1..1000,default 100)}`. Re-export from `index.ts`.
- [x] **Catalog users** — `listUsers(): Promise<UserSummary[]>` (iterate `nodesByLabel('User')`, sort by username), `deleteUser(username)` (detach-delete the node + `deleteSessionsForUser`), `setUserAdmin(username, isAdmin)` (`setNodeProps`), `resetPassword(username, hash)` (`setNodeProps` + `deleteSessionsForUser` so existing sessions die). TDD in `catalog.test.ts`.
- [x] **Catalog audit** — add a unique index on `(Audit, seq)` in `open()`. Maintain an in-memory `#auditSeq` seeded at `open()` from the current max `seq` among `nodesByLabel('Audit')` (0 if none). `recordAudit({username, action, target, detail?})`: increment seq, capture a **real** timestamp (`new Date().toISOString()` — NOT the constant `nowIso()`), create `(:Audit {seq, at, username, action, target, detail})`. `listAudit(limit): Promise<AuditEntry[]>` returns the highest-`seq` entries first, capped at `limit`. TDD: ordering is by seq desc; survives reopen (seq continues, no collision).
- [x] **requireAdmin** — in `auth.ts`, `requireAdmin(catalog)` returns a preHandler that runs `authenticate`, throws `HttpError(401,'UNAUTHENTICATED',…)` if absent, then `HttpError(403,'FORBIDDEN','admin privileges required')` if `!principal.isAdmin`, else sets `req.principal`.
- [x] **users routes** (`routes/users.ts`, all `requireAdmin`): `GET /api/users` → `listUsers()`. `POST /api/users` (201) → parse `CreateUserReq`, 409 if `findUser` exists, `createUser(username, await hashPassword(password), isAdmin ?? false)`, `recordAudit(action:'user:create', target:username)`. `PATCH /api/users/:username` (204) → `UpdateUserReq`; **guard:** refuse to demote the last admin (count admins via `listUsers`) → 409 `CONSTRAINT_VIOLATION`; audit `user:update`. `POST /api/users/:username/password` (204) → `ResetPasswordReq`, `resetPassword`; audit `user:password-reset`. `DELETE /api/users/:username` (204) → **guard:** refuse self-delete and last-admin-delete → 409; `deleteUser`; audit `user:delete`. Use `hashPassword` from `crypto.js`.
- [x] **audit route** (`routes/audit.ts`, `requireAdmin`): `GET /api/audit` → parse `ListAuditQuery` from `req.query`, return `listAudit(limit)`.
- [x] **Thread audit recording** into `data.ts`/`io.ts`/`databases.ts`/`query.ts` per anchors — always after the mutation succeeds, `action` like `node:create`/`edge:delete`/`db:create`/`role:grant`/`import`/`seed`/`query:write`, `target` the db name (or node/edge id where natural). Keep it a one-liner per site; do not change success/error semantics.
- [x] **Register** users + audit routes in `app.ts`.
- [x] **Client SDK** (`client/src/index.ts`): `listUsers()`, `createUser(username,password,isAdmin?)`, `updateUser(username,{isAdmin})`, `resetUserPassword(username,password)`, `deleteUser(username)`, `listAudit(limit?)`, `patchDatabase(name,{description})`. Re-export `UserSummary`/`AuditEntry`. Match existing fetch/error-handling style.
- [x] **Web SDK seam** (`atlas-api.ts`): add a pass-through per new client method (signatures mirroring the client). This is the ONLY web file Task 1 touches; Tasks 2 & 3 consume these.
- [x] Self-review: no read path records audit; last-admin guards covered by tests; reopen-continuity test for audit seq; `pnpm build` + targeted vitest green.

## Plan self-review

- **Conflict-freedom:** T2 and T3 touch disjoint dirs (`admin/` vs `workspace/`) and both depend only on T1's `atlas-api.ts` additions → they can run in parallel after T1. T1 owns every shared seam (protocol, client, atlas-api, app.ts).
- **Engine untouched:** audit reuses the catalog-as-Atlas-db dogfooding pattern; no WAL/format/migration risk. The only ordering subtlety (the constant `nowIso()`) is called out explicitly — audit uses a real timestamp + a monotonic seq seeded at open.
- **Security:** all new endpoints are `requireAdmin`; last-admin / self-delete guards prevent lockout; password reset kills existing sessions; audit is read-only to admins.
- **Scope discipline:** audit covers the write paths enumerated in §anchors; it is not a generic event bus. Squiggle complements (does not replace) the shipped banner.
- **Gate:** ends with `pnpm build && pnpm typecheck:test && pnpm lint && pnpm format && pnpm vitest run && pnpm -F web exec ng test --watch=false && pnpm -F web e2e && pnpm verify:dist` all green, plus CHANGELOG/README/version bump to 1.1.0.
